# ПУТ 1.4.0

## Изменения для оператора

- В «Плане закупок» выберите организацию и склад. Расчёт использует их резервы, складские остатки и ожидаемые поставки. Одноимённые товары попадают в отдельные строки. Перед проведением заказа форма сверяет потребность заново. Для роли «Снабженец» доступен подбор закупочной цены.
- В кассовых и банковских документах можно распределить одну оплату по нескольким реализациям покупателя или поступлениям от поставщика. Разница между суммой платежа и суммой строк учитывается как аванс. Документ даёт одно движение денег. Отчёты показывают погашение долга по каждому основанию. [Как разнести платёж](help/money.md)
- В строках заказа поставщику появилось поле «Подтверждённая дата поставки». Отчёт об исполнении заказов покупателей показывает первую дату, к которой хватит товара для полной отгрузки. Он учитывает чужие резервы, приёмку, снятую потребность и привязку к заказу покупателя. [Как получить прогноз](help/orders.md)
- В «ABC-анализе продаж» появились класс, доля и накопленная доля положительной валовой прибыли. Границы по умолчанию — 80 и 95 %. Возвраты уменьшают вклад товара. [Как читать отчёт](help/trade.md)

## Первый запуск

Распакуйте архив для Windows x64. Из каталога, содержащего `START-HERE.txt`, выполните `.\scripts\start_preview.ps1`. Скрипт откроет локальный стенд и запишет пароль пользователя `preview` в `.local/credentials.txt`. В архив включена проверенная сборка OneBase `0.13.0+put.6.ac6231b8`. [Локальный стенд](LOCAL_PREVIEW.md)

## Обновление с 1.3.4

1. Сделайте резервную копию базы и файлов. Примените метаданные 1.4.0 обычным способом обслуживания вашей базы. Для файловой конфигурации выполните `onebase migrate` с её каталогом и SQLite. Для конфигурации, хранящейся в БД, используйте `onebase deploy`. Проверьте версию платформы по [инструкции](../platform-patches/README.md).
2. После обновления схемы заполните организацию в ранее записанных движениях резервов. В PostgreSQL выполните `psql -X -v ON_ERROR_STOP=1 -d <имя_БД> -f scripts/backfill_reservation_owners.sql`. Для SQLite из корня конфигурации выполните `sqlite3 <файл_БД> ".read scripts/backfill_reservation_owners.sql"`. Скрипт определяет организацию по заказу покупателя. Повторный запуск пропускает уже заполненные строки. На новой базе организация записывается при проведении. [Скрипт обновления](../scripts/backfill_reservation_owners.sql)
3. Откройте «Свободные остатки товаров» и «План закупок» на одной организации и складе. В существующих заказах поставщику дату поставки можно заполнить после подтверждения поставщиком. Без даты отчёт продолжает показывать количество товара в пути.
4. Для переноса в БП 3.0 платежей с распределением требуется приёмник с поддержкой формата 1.1. Выгрузка без таких платежей сохраняет формат 1.0. [Состав и версии обмена](BP3_EXCHANGE.md)
