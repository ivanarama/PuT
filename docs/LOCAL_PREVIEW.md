# Локальный стенд PuT

Иллюстрированное руководство: **http://127.0.0.1:8100/ui/help**. Обновление снимков платформенной командой и автономный HTML-экспорт описаны в [HELP_SCREENSHOTS.md](HELP_SCREENSHOTS.md).

Изменения подготовлены в ветке `codex/platform-refresh-20261021`. Локальная SQLite изолирована от PostgreSQL на Orange Pi.

Стенд: **http://127.0.0.1:8100/ui/**. Логин администратора `preview`; случайный пароль хранится только локально в `.local/credentials.txt`. База `.local/preview.db` отдельная, доступ только с этого компьютера. Журналы — `.local/server*.log`.

На подготовленном стенде также есть пять пользователей для сравнения меню ролей: их логины и пароли записаны в `.local/role-credentials.json`.

Запуск из корня проекта:

```powershell
./scripts/start_preview.ps1
```

Для нового клона сначала соберите платформу по инструкции `platform-patches/README.md`. Скрипт запуска создаст отсутствующую SQLite, заполнит демо и создаст администратора. Существующие данные он не очищает. Ночной сброс отдельно описан в `DEMO_RESET.md`.

Проверка результата:

1. Главная: показатели месяца, рейтинги и ожидаемые поставки. Нажмите строку таблицы для открытия карточки. «Отборы» раскрываются по нажатию. Изменения документов обновляют связанные виджеты.
2. Контрагент: долг, просрочка, кредитный лимит, неоплаченные документы, заказы и история. «Ввести на основании» открывает несохранённый заказ или счёт с заполненным клиентом.
3. Номенклатура: остатки по складам, резерв, свободное количество, товары в пути, текущие цены и движения. Цветные области разделяют сведения; таблицы сводок нельзя редактировать.
4. Заказ покупателя/поставщику: строгие этапы обработки и история. Завершение и отмена проверяют незакрытое обеспечение.
5. Сборка товаров: выберите готовое изделие — список спецификаций ограничится этим изделием. Кнопка заполнения заменяет состав документа выбранной спецификацией.
6. Импорт номенклатуры, выгрузка БП3, закрытие месяца: запуск в очереди и обновление результата. Номер задания можно сохранить и вставить после повторного открытия формы. Повторный клик до окончания возвращает текущую задачу, не меняя её параметры.
7. Панель руководителя: `/ui/page/Панель`. Показывает показатели месяца и открытые заказы со ссылками. Меню остальных ролей ограничено их ежедневными задачами; административные права остаются у администратора.

Проверки:

```powershell
.local/onebase-preview.exe --no-gui check --project .
.local/onebase-preview.exe --no-gui lint --project .
go test ./...
python -X utf8 scripts/test_demo_reset.py --onebase .local/onebase-preview.exe
.local/onebase-preview.exe --no-gui test --project . --sqlite .local/verification.db
```

Перед `onebase test` мигрируйте и заполните отдельную проверочную базу. `scripts/scenario_tests.sh` создаёт две отдельные временные базы и проверяет движения и загрузку ЭДО. Артефакты локальной проверки и снимки интерфейса находятся в `.local/`; они не входят в Git. Линт оставляет предупреждения об обработках только для администратора (загрузка ЭДО/дампа, закрытие, заполнение демо).
