# PuT — руководство оператора

Краткие сценарии ежедневной работы. Технические детали — в README.md и DOCS.md.

## Роли

| Роль | Что умеет |
|------|-----------|
| Кладовщик | Складские документы (поступление, оприходование, списание, перемещение, пересчёт, сборка/разборка), отгрузка и возвраты; АРМ приёмки, инвентаризация склада, отгрузка заказов |
| Менеджер | Продажи: заказы покупателей, счета, реализации, возвраты от покупателей, приходные ордера, установка цен, корректировка долга; АРМ продавца |
| Снабженец | Закупки: заказы поставщикам, поступления, возвраты поставщикам, корректировка долга; план закупок |
| Кассир | Касса: ПКО/РКО, РМК; банк: поступление на расчётный счёт, списание с расчётного счёта, загрузка выписки |
| Управленец | Просмотр документов всех разделов и отчёты (баланс, валовая прибыль, книги); документов не создаёт |
| Демо | Демо-стенд: документы, отчёты и рабочие места всех разделов |

Загрузку ЭДО, загрузку дампа 1С и закрытие месяца роли пока не получают — эти
операции выполняет администратор (см. «Администратору»).

## Типовые операции

### Продажа со склада (АРМ Продавца)
1. Продажи → АРМ Продавца: выберите покупателя и склад; тип цен подставится из карточки покупателя.
2. Товар: скан штрихкода в поле «Штрихкод» или кнопка «Подбор» (по свободному остатку). Повторный скан того же товара увеличивает количество в строке. Если тип цен не выбран, сканер подставит тип по умолчанию.
3. «Оформить продажу» (вкладка «Товары») — создаётся и проводится реализация; флажок «Оплатить сразу» дополнительно создаст ПКО в кассу.

Штрихкоды заводятся в справочнике «Штрихкоды номенклатуры»: один штрихкод — один товар,
повтор не записывается.

### Закупка по ЭДО
1. Полученный УПД (XML) сохраните на диск.
2. Закупки → «Сопоставление и загрузка документов ЭДО (УПД)»: укажите файл, при необходимости склад/поставщика.
3. «Загрузить и сопоставить позиции» — проверьте таблицу сопоставления. Не найденную номенклатуру создайте кнопкой «Создать отсутствующую номенклатуру» или флажком «Автоматически создавать отсутствующую номенклатуру»; с флажком загрузка создаёт и неизвестного поставщика по ИНН (вид «Поставщик»).
4. «Создать и провести Поступление». Повторная загрузка того же УПД не создаёт дубль.

### Пересчёт товаров (инвентаризация)
1. Склад → Пересчёт товаров: организация и склад подставятся по умолчанию, при необходимости смените.
2. «Заполнить по учётным остаткам» — остатки организации на складе на дату пересчёта; внесите фактические количества.
3. «Оформить излишки и недостачи» — пересчёт записывается, в одной транзакции создаются и проводятся Оприходование (излишки, по средней цене партий организации) и Списание (недостачи, по ФИФО). Повторно оформить тот же пересчёт нельзя — система назовёт уже созданные документы.

### Просроченная задолженность
Продажи → Оплаты по реализациям: колонка «Просрочено» — непогашенный остаток по
документам, у которых срок оплаты раньше даты «Просрочка на дату» (по умолчанию —
сегодня). В день срока долг ещё не просрочен; реализация без срока оплаты
просроченной не считается. Срок заполняется в документе реализации. Долг перед
поставщиками — так же, в Закупки → «Оплаты поставщикам по поступлениям».

## Регламент

- **Закрытие месяца** (обработка «Закрытие месяца и расчёт себестоимости»): перепроводит проведённые складские и торговые документы периода по хронологии — пересчёт себестоимости ФИФО. Период: с/по даты, пусто — вся база; можно выбрать организацию. Закрытый период (по дату запрета) не перепроводится. Флажок «Закрыть период (установить дату запрета по дату окончания)» ставит дату запрета, только если дата окончания указана и ошибок проведения нет. По дату запрета нельзя записать, провести, отменить проведение или удалить документ, а также перенести дату документа в закрытый период или из него.
- **Обмен с 1С**: данные из УТ 10/11 выгружаются обработками из `tools/` (`ВыгрузкаВOneBase_УТ10`, `ВыгрузкаВOneBase_УТ11`) и загружаются обработкой «Загрузка дампа 1С». Загрузка идемпотентна: повтор сопоставляет объекты по реквизиту «Идентификатор1С», а не создаёт дубли. Выгрузка в 1С:Бухгалтерию 3.0 — обработка «Выгрузка в 1С:Бухгалтерию (БП3)».

## Администратору

- После обновления конфигурации выполните `onebase migrate` на каждой базе (новые реквизиты/регистры).
- Резервные копии: `onebase backup`.
- Проверка конфигурации: `onebase check`; тесты конфигурации: `onebase test --project . --sqlite <база>` (в CI идут после заполнения демо-базы); сценарные тесты: `bash scripts/scenario_tests.sh`.
- Права на загрузку ЭДО, загрузку дампа 1С и закрытие месяца ролям не выданы. Если эти операции выполняет не администратор, выдайте право в `roles/*.yaml` (`processors: <Имя>: [run]`); для автосоздания номенклатуры при загрузке ЭДО роли нужна и запись справочника «Номенклатура».
