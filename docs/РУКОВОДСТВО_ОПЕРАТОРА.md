# PuT — руководство оператора

Краткие сценарии ежедневной работы. Технические детали — в README.md и DOCS.md.

## Роли

| Роль | Что умеет |
|------|-----------|
| Кладовщик | Складские документы (поступление, списание, перемещение, пересчёт, сборка/разборка), АРМ приёмки |
| Менеджер | Продажи: заказы, счёта, реализации, АРМ продавца, взаиморасчёты |
| Снабженец | Закупки: заказы поставщикам, поступления, взаиморасчёты |
| Кассир | Касса: ПКО/РКО, РМК |
| Управленец | Всё + отчёты (баланс, валовая прибыль, книги) |
| Демо | Полные права (демо-стенд) |

## Типовые операции

### Продажа со склада (АРМ Продавца)
1. Продажи → АРМ Продавца: выберите покупателя, склад, тип цен.
2. Товар: скан штрихкода в поле «Штрихкод» или кнопка «Подбор» (по свободному остатку).
3. «Оформить продажу» — создаётся и проводится реализация; флажок «Оплатить сразу» дополнительно создаст ПКО в кассу.

### Закупка по ЭДО
1. Полученный УПД (XML) сохраните на диск.
2. Закупки → Загрузка ЭДО: укажите файл, при необходимости склад/поставщика.
3. «Загрузить и сопоставить» — проверьте таблицу сопоставления (не найденное создайте вручную или флажком автосоздания).
4. «Создать и провести». Повторная загрузка того же УПД не создаёт дубль (защита по номеру).

### Пересчёт товаров (инвентаризация)
1. Склад → Пересчёт товаров: склад, организация.
2. «Заполнить по учётным остаткам» → внесите фактические количества.
3. «Оформить излишки и недостачи» — создадутся и проведутся Оприходование (излишки, по средней цене партий) и Списание (недостачи, по ФИФО).

### Просроченная дебиторка
Продажи → Оплаты по реализациям: колонка «Просрочено» показывает непогашенный остаток по документам с прошедшим сроком оплаты (срок заполняется в документе реализации).

## Регламент

- **Закрытие месяца**: обработка «Закрытие месяца» перепроводит складские и торговые документы хронологически (пересчёт ФИФО). Период: с/по даты; пусто — вся база.
- **Сверка с 1С**: экспортёр из 1С (tools/) → загрузка дампа обработкой «ЗагрузкаДампа1С» (идемпотентна по реквизиту «Идентификатор1С») → сравнение с golden-файлами (см. docs/ИНСТРУКЦИЯ_ОБМЕН_И_СВЕРКА_1С.md).

## Администратору

- После обновления конфигурации выполните `onebase migrate` на каждой базе (новые реквизиты/регистры).
- Резервные копии: `onebase backup`.
- Проверка конфигурации: `onebase check`, сценарные тесты: `bash scripts/scenario_tests.sh`.
