# PuT 1.3.4

Версия исправляет проведение возвратов, импорт выписок и приёмку по заказам. Она добавляет журнал обменов и сверку документов перед закрытием месяца. Поставка включает OneBase `0.13.0+put.4.ac6231b8` с исправлением расчёта остатков и оборотов по регистрам со ссылочными реквизитами в PostgreSQL.

## Обновление существующей базы

1. Подготовьте копию базы вместе с файлами и установите сборку платформы для 1.3.4. Проверьте её командой `python scripts/check_runtime.py --onebase <путь к бинарю>`. Примените конфигурацию и миграцию схемы к копии тем же способом, которым обслуживается эта база. Новые поля связывают строки поступления и возврата с исходным заказом и реализацией. В банковских документах появилось поле для распознавания повторного импорта.
2. Откройте «Касса и банк → Отчёты о деньгах → Сверка учёта» или укажите дату окончания в «Закрытии месяца» и нажмите «Сверить учёт на дату окончания». Сверка читает документы и движения. Для предполагаемых дублей платежей сопоставьте номер, дату, счёт, сторону и сумму с оригиналом банка. Если использовали импорт из 1С, повторное чтение исходного дампа выявит расхождения с ранее принятыми документами по GUID.
3. Проверьте в копии возврат скидочной продажи, частичную приёмку заказа, повтор одной выписки и результат сверки. Исправление уже проведённых документов и повторное закрытие периода — отдельные учётные операции. Перенос конфигурации сам по себе их не выполняет.

## Изменения для оператора

- Банк показывает предпросмотр без создания контрагентов. При загрузке распознаются повторные операции и несовпадения реквизитов. В «Настройки → Обмен данными → Сверка обменов» можно выбрать файл, увидеть все его строки, отобрать ошибки и повторить конкретный банковский платёж. При импорте УПД проверяется организация покупателя. Импорт исходной базы 1С проверяет строки документа до проведения. Обработки выгрузки УТ сохраняют исходное обозначение ставки НДС.
- Возврат покупателю учитывает скидку и ранее возвращённое по строке продажи. Возврат услуги сохраняет финансовое сторно без прихода на склад. Кассовые и банковские документы проверяют стороны расчёта по основанию.
- В АРМ продавца проведение реализации и немедленной оплаты выполняется в одной транзакции. Приёмка переносит товар, назначение, цену и НДС из заказа. Частичное закрытие заказа уменьшает количество и стоимость в пути. Инвентаризация берёт количество и себестоимость выбранной организации. Излишки и недостачи записываются одной транзакцией.
- В отчётах об оплатах доступны входящий долг, обороты и конечный долг. Платёжный календарь показывает ожидаемые суммы по открытым документам и срокам. Отчёты по заказам отражают резерв, поставку и исполнение.
- Дата запрета продвигается после проверки общего открытого периода. Сверка сопоставляет начисление долга с суммой документа, остатки партий со складом, движения товаров в пути со строками заказов, поступлений и закрытий. Из каждого отклонения можно перейти к регистратору. Для руководителя доступны отчёты и сверка. Из роли руководителя исключены запись документов и запуск обработок, меняющих учёт.
- При занятой очереди запрос с другими параметрами выводит сообщение для оператора. Период выгрузки БП3 отбирается при чтении идентификаторов, основания загружаются по ссылке. Формат обмена сохраняет версию 1.0.

Для сверки из CLI и разбора результата закрытия см. [длительные операции](help/jobs.md). Порядок восстановления файлов и базы демо описан в [руководстве по сбросу](DEMO_RESET.md).

## Измерение выгрузки за один день

В тестовую базу добавили 3 000 счетов с датами за год за пределами выбранного дня. Обе версии выгрузили одинаковые 16 документов с основаниями. На SQLite время сократилось с 17,40 до 2,11 секунды, пиковая память процесса — с 86,0 до 64,6 МиБ. В отдельном прогоне на PostgreSQL 16 журнал сервера зафиксировал сокращение числа выполненных запросов чтения с 40 135 до 473. Это измерения на одной тестовой выборке.
