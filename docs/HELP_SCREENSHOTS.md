# Иллюстрированная справка PuT

Руководство открывается в приложении: `/ui/help`. В карточках, заказах и обработках кнопка «Справка» ведёт к соответствующей главе. Markdown, оглавление и PNG находятся в `docs/help/` и переносятся вместе с конфигурацией средствами OneBase.

В руководстве восемь глав и десять снимков настоящего интерфейса: меню продаж по задачам, главная, раскрытые отборы, клиент, товар, заказ, приходный кассовый ордер, результат закрытия месяца, сборка и АРМ продавца. Контекстная справка подключена ко всем 21 виду документов. Цветное оформление форм сохраняется на снимках.

## Обновление иллюстраций

Используйте только отдельную демонстрационную базу с вымышленными данными. `docs capture` выполняет действия браузера из сценария. Наш сценарий читает карточки и результат уже выполненного задания; сборку заполняет в незаписанной форме. Он не запускает закрытие месяца, не записывает и не проводит документы.

Понадобятся Node.js, Python 3, пакет Playwright и его Chromium. Установите браузерные зависимости **вне каталога конфигурации**, например в `D:/Tools/put-docs`:

```powershell
npm install --prefix D:/Tools/put-docs playwright
node D:/Tools/put-docs/node_modules/playwright/cli.js install chromium
```

Запустите локальный стенд командой `scripts/start_preview.ps1`. В демонстрационной базе должны быть стандартные клиент «Маленький стульчик», товар «Внезапно Зашатался», заказ покупателя, приходный кассовый ордер, хотя бы одна спецификация с изделием и успешно завершённое фоновое закрытие месяца. Для снимка результатов используется последнее успешное задание, повторное закрытие не запускается.

Сохраните сессию браузера **вне репозитория**. Команда ниже откроет браузер: войдите в локальный стенд и закройте окно, чтобы сохранить состояние входа. Файл содержит секретные cookies; не добавляйте его в Git или пакет конфигурации.

```powershell
node D:/Tools/put-docs/node_modules/playwright/cli.js codegen --save-storage "$env:TEMP/put-help-storage-state.json" http://127.0.0.1:8100/login
```

Из корня PuT подготовьте сценарий с идентификаторами текущей демобазы и запустите **платформенную** команду съёмки:

```powershell
python -X utf8 scripts/prepare_help_capture.py --sqlite .local/preview.db
.local/onebase-preview.exe docs capture --project . --scenario .local/help-capture.json --storage-state "$env:TEMP/put-help-storage-state.json" --playwright-module D:/Tools/put-docs/node_modules/playwright
.local/onebase-preview.exe docs check --project .
.local/onebase-preview.exe check --project .
```

Шаблон `docs/help/screenshots.template.json` хранит маршруты, действия, области снимков и маски. `scripts/prepare_help_capture.py` читает SQLite в режиме read-only и подставляет UUID, адрес стенда и даты. Готовый сценарий остаётся в игнорируемом `.local/`; в Git попадают только шаблон и итоговые `docs/help/images/*.png`. Номер фонового задания на снимке закрашен. После съёмки проверьте содержимое каждой иллюстрации и откройте справку в браузере.

## Автономная копия

```powershell
.local/onebase-preview.exe docs export --project . --output ../PuT-help-preview
```

Результат — HTML-руководство с изображениями и `bundle.json` для внешних издателей. Каталог экспорта должен находиться вне конфигурации. Его можно открыть без запущенной базы: `../PuT-help-preview/index.html`.
