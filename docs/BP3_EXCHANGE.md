# Обмен PuT → БП3, версия 1

Выгрузка переносит документы OneBase/PuT 1.3.3 в типовую «1С:Бухгалтерию
предприятия», редакция 3.0. Приёмник — внешняя обработка `PuT-BP3_v1.epf`.
Проверенная версия БП — 3.0.188.22, платформа 8.3.27.2074.

## Установка файлов выгрузки

Сохраните копию заменяемых файлов конфигурации PuT. Распакуйте
`PuT-BP3-export-v1.zip` в её каталог с сохранением структуры: обновляются
описание обработки, её модуль и два файла управляемой формы. Архив не содержит
базу данных. Выполните `onebase check --project <каталог PuT>` и перезапустите
локальный сервер OneBase. Если конфигурация хранится в БД, примените её штатным
способом развёртывания; одного копирования файлов на компьютер с браузером
недостаточно. Используйте поддерживаемую сборку OneBase 0.13.0+put.3.ac6231b8.

В БП достаточно открыть `PuT-BP3_v1.epf`; изменение конфигурации или расширение
не требуется. Для первой проверки используйте копию вашей БП.

## Как выполнить перенос

1. В PuT откройте «Выгрузка в 1С:Бухгалтерию (БП3)».
2. Задайте код исходной базы. Пустое поле означает `PuT`. Сохраняйте этот код
   одинаковым при повторных выгрузках; для разных баз используйте разные коды.
3. Укажите путь JSON, при необходимости период и «Только проведённые документы».
   Путь относится к компьютеру, где работает сервер OneBase. Для удалённого
   сервера скопируйте готовый JSON с него на компьютер с БП.
4. Нажмите «Поставить в очередь», затем «Обновить результат». Дождитесь «Выполнено».
5. В БП откройте EPF, выберите JSON и нажмите «Прочитать файл».
6. Проверьте соответствия организаций, контрагентов, номенклатуры и складов.
   При неоднозначном поиске укажите объект БП вручную. Можно сопоставить и документ.
7. Отметьте документы и нажмите «Загрузить выбранные».

По умолчанию документы записываются без проведения. Флаг «Проводить по признаку
источника» проводит только документы, проведённые в PuT; необходимы настроенная
учётная политика, остатки и аналитика БП. Организация, созданная из PuT, требует
настройки учёта в БП. Проверка записи всех видов не означает проверку всех
вариантов бухгалтерского проведения на рабочей базе.

Без «Перезаписывать загруженные документы» повтор пропускает существующие
документы. С этим флагом переносимые строки заменяются. Связи сохраняются по
коду базы, виду документа и UUID, а не по номеру. Проведённый документ защищён
от перезаписи с выключенным флагом проведения.

## Состав

| PuT | БП3 |
|---|---|
| Счёт | Счёт покупателю |
| Поступление товаров | Поступление товаров и услуг |
| Реализация товаров | Реализация товаров и услуг |
| Возврат от покупателя | Возврат товаров от покупателя |
| Возврат поставщику | Возврат товаров поставщику |
| Приходный кассовый ордер | Приходный кассовый ордер |
| Расходный кассовый ордер | Расходный кассовый ордер |
| Поступление на расчётный счёт | Поступление на расчётный счёт |
| Списание с расчётного счёта | Списание с расчётного счёта |
| Корректировка долга | Корректировка долга |
| Перемещение товаров | Перемещение товаров |
| Оприходование товаров | Оприходование товаров |
| Списание товаров | Списание товаров |
| Сборка товаров | Комплектация номенклатуры |
| Разборка товаров | Разукомплектация номенклатуры |
| Пересчёт товаров | Инвентаризация товаров на складе |
| Установка цен | Установка цен номенклатуры |

Если у сборки несколько выходных изделий или у разборки несколько исходных,
создаётся отчёт производства за смену: сохраняются все входы и выходы.
Себестоимость в этих документах рассчитывается средствами БП.

По согласованному решению заказы покупателей, заказы поставщикам и оба вида
закрытия заказов **не переносятся**. Их исходные UUID остаются в сохранённых
данных источника; документы заказов в БП не создаются. Расширение не требуется.

Документы-основания добавляются в выгрузку даже за границами периода и помечаются
`dependency`. В БП отметьте основание вместе с зависимым документом либо ранее
перенесите основание. При отсутствии основания загрузка выдаёт понятную ошибку.
Весь выбранный пакет записывается в одной транзакции: ошибка откатывает его целиком.

В PuT нет валюты и договора в шапках переносимых документов. Обмен использует
валюту регламентированного учёта БП, курс и кратность 1, договор «Основной договор
PuT» нужного вида для каждой пары организация/контрагент. Банковские счета
сопоставляются по владельцу и номеру, кассовые документы используют счёт 50.01.
Товарные счета по умолчанию 41.01; аналитика и проведение требуют проверки в БП.

## Разработка и проверка

`scripts/generate_bp3_exporter.py` создаёт читатели объектов из YAML и схему
`docs/bp3-schema.json`. Правьте шаблон `tools/bp3/exporter-common.os` и генератор,
а не сгенерированные читатели. Проверки:

```sh
python scripts/generate_bp3_exporter.py --check
onebase check --project .
python scripts/test_bp3_export.py --onebase /path/to/onebase
```

Последняя проверка создаёт отдельную тестовую SQLite, проверяет все 17 видов,
исключение заказов, режим только проведённых, период с основаниями и отказ на
неверной дате. Рабочая база для этого не используется.
