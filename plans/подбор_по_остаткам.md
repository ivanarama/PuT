# План: Подбор товаров по остаткам (issue #27)

## Контекст

В 1С у расходных документов есть кнопка **«Подбор»**: открывает список номенклатуры
с остатком на складе документа, пользователь отмечает позиции и количества — строки
попадают в табличную часть. Это **епархия конфигурации**, а не платформы: логика
«что считать остатком» (резервы, партии, склад) живёт в прикладном коде.

Эталонный документ — **РеализацияТоваров** (`documents/реализация_товаров.yaml`,
форма `forms/реализациятоваров/`). После отладки — тиражируем на остальные расходные.

## Модель свободного остатка (Склад + минус резервы)

Уже реализована в `src/утилиты.module.os` → `ПроверитьСвободныйОстаток` (строка 170).
Подбор использует **ту же** формулу, чтобы предлагать ровно то, что потом пройдёт
контроль при проведении:

```
Свободно(Ном) = ОстатокПартий(Ном, Склад, Организация) − ЧужиеРезервы(Ном, Склад)
```

- **Остаток** — `РегистрНакопления.ПартииТоваров.Остатки(&МоментВремени)` по
  `Склад` + `Организация`, агрегат `КоличествоОстаток > 0` (тот же источник, что и ФИФО).
- **Чужие резервы** — `РегистрНакопления.РезервыТоваров.Остатки(&МоментВремени)` по
  `Склад`, исключая `ЗаказПокупателя = СвойЗаказ` документа (свой резерв подбору не мешает).
- `МоментВремени` — для нового/непроведённого документа берём `ТекущаяДата()`
  (у объекта ещё нет `МоментВремени()`); для записанного — `Объект.Ссылка.МоментВремени()`.

> Регистр `ОстаткиТоваров` тоже годится как источник остатка (он без партий и проще),
> но для согласованности с проверкой при проведении берём `ПартииТоваров` — иначе подбор
> мог бы предложить позицию, которую ФИФО потом не найдёт в нужной партии.

## Объём итерации

Делаем **этап 1** (чистая конфигурация, отгружаем сейчас). **Этап 2** —
по согласованию, требует доработки движка.

## Этап 1 — «Заполнить по остаткам» (чистая конфигурация)

Кнопка на вкладке «Товары» формы реализации, серверный обработчик заполняет ТЧ
кандидатами: все номенклатуры со свободным остатком > 0 на складе документа.
Количество по умолчанию = свободный остаток (пользователь правит/удаляет лишнее),
цена подтягивается через существующую `ПолучитьЦену`.

Механизм уже поддержан движком: управляемая форма исполняет `obFire('Имя','Нажатие')`
→ серверный обработчик в `.form.os` → ре-рендер формы с новыми строками
(см. `КнопкаОчиститьНажатие`, который вызывает `Объект.Товары.Очистить()`).

### Изменения

**1. Общая функция подбора — `src/утилиты.module.os`** (рядом с `ПроверитьСвободныйОстаток`):

```
// Возвращает Массив структур {Номенклатура, Свободно} со свободным остатком > 0
// на складе. СвойЗаказ — заказ текущего документа (его резерв не вычитается),
// Неопределено если заказа нет.
Функция СвободныеОстаткиСклада(Склад, Организация, СвойЗаказ, МоментВремени) Экспорт
```

Тело — переиспользует запросы из `ПроверитьСвободныйОстаток` без списка номенклатуры
(берём всё по складу), возвращает результат вместо `ВызватьИсключение`. Чтобы не
дублировать SQL — вынести два запроса (резервы, партии) в локальные хелперы и звать
из обеих процедур.

**2. Кнопка в форме — `forms/реализациятоваров/формаобъекта.form.yaml`**
(вкладка `СтраницаТовары`, рядом с `КнопкаОчистить`):

```yaml
- kind: Кнопка
  name: КнопкаПодбор
  title:
    ru: "Заполнить по остаткам"
    en: "Fill from balances"
    de: "Aus Beständen füllen"
    sr: "Попуни из стања"
  hint: "Добавить товары со свободным остатком на складе документа"
  events:
    Нажатие: КнопкаПодборНажатие
```

**3. Обработчик — `forms/реализациятоваров/формаобъекта.form.os`** (`&НаСервере`):

```
Процедура КнопкаПодборНажатие()
    Если НЕ ЗначениеЗаполнено(Объект.Склад) Тогда
        ВызватьИсключение("Сначала укажите склад отгрузки");
    КонецЕсли;
    Орг = ?(ЗначениеЗаполнено(Объект.Организация), Объект.Организация, ОрганизацияПоУмолчанию());
    Момент = ?(ЗначениеЗаполнено(Объект.Дата), Объект.Дата, ТекущаяДата());

    // уже добавленные позиции — чтобы не дублировать
    Есть = Новый Соответствие;
    Для Каждого Стр Из Объект.Товары Цикл
        Есть.Вставить(Стр.Номенклатура, Истина);
    КонецЦикла;

    Кандидаты = СвободныеОстаткиСклада(Объект.Склад, Орг, Объект.ЗаказПокупателя, Момент);
    Добавлено = 0;
    Для Каждого К Из Кандидаты Цикл
        Если Есть.Получить(К.Номенклатура) <> Неопределено Тогда Продолжить; КонецЕсли;
        Нов = Объект.Товары.Добавить();
        Нов.Номенклатура = К.Номенклатура;
        Нов.Количество   = К.Свободно;
        Если ЗначениеЗаполнено(Объект.ТипЦенПродажи) Тогда
            Нов.Цена = ПолучитьЦену(К.Номенклатура, Объект.ТипЦенПродажи, Объект.Дата);
        КонецЕсли;
        Добавлено = Добавлено + 1;
    КонецЦикла;

    ПересчитатьИтоги();
    Сообщить(?(Добавлено = 0, "Свободных остатков на складе нет",
        "Добавлено позиций: " + Строка(Добавлено)));
КонецПроцедуры
```

### Проверка этапа 1

- `onebase check` — зелёный (синтаксис формы + компиляция запросов).
- Тестовая база (`заполнитьтестовуюбазу`): открыть новую РеализациюТоваров, указать
  склад → «Заполнить по остаткам» → строки появились, количества = свободный остаток.
- Зарезервированный под чужой заказ товар **не** предлагается сверх свободного.
- Провести документ — контроль `ПроверитьСвободныйОстаток` не должен ругаться на
  автозаполненные строки (формулы согласованы).

## Этап 2 — интерактивный диалог подбора (требует движка)

Полноценный 1С-подобный подбор: модальный список номенклатуры с колонкой «Свободно»,
чекбоксы + ввод количества, поиск/фильтр, кнопка «Перенести в документ». Возвращает
**выбранные** строки, а не все.

Сейчас управляемые формы движка такого примитива не имеют (есть только `openRefPicker`
для выбора **одной** ссылки — `internal/ui/templates_managed.go`). Нужна доработка
платформы — выбор делать в репозитории `onebase`, не здесь:

- Примитив «форма выбора с множественным результатом» (таблица + чекбоксы + числовой
  ввод), вызываемый из обработчика управляемой формы и возвращающий массив структур.
- Конфигурация описывает источник (запрос свободных остатков из этапа 1) и маппинг
  колонок результата на поля ТЧ.

До появления примитива этап 1 закрывает задачу практически: автозаполнение + ручная
правка количеств покрывает основной сценарий «отгрузить что есть на складе».

## Тиражирование (после отладки на реализации)

Те же кнопка + обработчик (через общую `СвободныеОстаткиСклада`) для расходных:
`ПеремещениеТоваров`, `СписаниеТоваров`, `ВозвратПоставщику`. Для `ЗаказПокупателя`
подбор по остаткам тоже уместен (резервирование), но там «свободно» считается без
вычитания собственного будущего резерва — вынести параметром.
