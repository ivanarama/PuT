# План: Заказы с резервированием

## Контекст

Для управления закупками и продажами нужны плановые документы:
- **Заказ покупателя** — фиксирует заявку клиента, резервирует товар на складе
- **Заказ поставщику** — фиксирует заказ поставщику, отслеживает товары в пути

Оба заказа «закрываются» фактическими документами (Реализация / Поступление), созданными на их основании. Поддерживается частичное выполнение — один заказ может быть покрыт несколькими реализациями/поступлениями.

---

## Общая схема документооборота

```
ПРОДАЖИ:
  Счёт → ЗаказПокупателя → РеализацияТоваров → (оплаты)
                ↓ резерв               ↓ снимает резерв
          РезервыТоваров(+)      РезервыТоваров(-)

ЗАКУПКИ:
  ЗаказПоставщику → ПоступлениеТоваров → (оплаты)
        ↓ ожидание            ↓ снимает ожидание
  ТоварыВПути(+)        ТоварыВПути(-)
```

---

## Новые регистры накопления

### 1. РезервыТоваров

Отслеживает, сколько товара зарезервировано под заказы покупателей.

| Сечение | Поле | Тип |
|---------|------|-----|
| Измерение | Номенклатура | reference:Номенклатура |
| Измерение | Склад | reference:Склад |
| Измерение | ЗаказПокупателя | reference:ЗаказПокупателя |
| Ресурс | Количество | number |

**Движения:**
- ЗаказПокупателя (posting) → Приход (резервирует)
- РеализацияТоваров (posting) → Расход (снимает резерв по заказу)

### 2. ТоварыВПути

Отслеживает ожидаемые поступления от поставщиков.

| Сечение | Поле | Тип |
|---------|------|-----|
| Измерение | Номенклатура | reference:Номенклатура |
| Измерение | Склад | reference:Склад |
| Измерение | ЗаказПоставщику | reference:ЗаказПоставщику |
| Ресурс | Количество | number |
| Ресурс | Сумма | number |

**Движения:**
- ЗаказПоставщику (posting) → Приход (ожидание)
- ПоступлениеТоваров (posting) → Расход (закрывает ожидание)

## Доработка существующих документов

### РеализацияТоваров

**Добавить поле:**
- `ЗаказПокупателя` (reference:ЗаказПокупателя) — связка с заказом

**Добавить based_on:**
```yaml
based_on:
  - Счёт
  - ЗаказПокупателя
```

**Доработка posting (`src/реализациятоваров.posting.os`):**
После существующей логики ФИФО-списания добавить:

```
Если ЗначениеЗаполнено(this.ЗаказПокупателя) Тогда
    // Снять резерв по заказу покупателя
    Для Каждого Строка Из this.Товары Цикл
        ДвР = Движения.РезервыТоваров.Добавить();
        ДвР.ВидДвижения  = "Расход";
        ДвР.Номенклатура = Строка.Номенклатура;
        ДвР.Склад        = this.Склад;
        ДвР.ЗаказПокупателя = this.ЗаказПокупателя;
        ДвР.Количество   = Строка.Количество;
    КонецЦикла;
КонецЕсли;
```

**Доработка формы:** добавить поле ЗаказПокупателя на вкладку «Покупатель и склад»

### ПоступлениеТоваров

**Добавить поле:**
- `ЗаказПоставщику` (reference:ЗаказПоставщику) — связка с заказом

**Добавить based_on:**
```yaml
based_on:
  - ЗаказПоставщику
```

**Доработка posting (`src/поступлениетоваров.posting.os`):**
После существующей логики добавить:

```
Если ЗначениеЗаполнено(this.ЗаказПоставщику) Тогда
    // Снять ожидание товаров в пути
    Для Каждого Строка Из this.Товары Цикл
        НеттоСтроки = Строка.Сумма - Строка.СуммаНДС;
        ДвТП = Движения.ТоварыВПути.Добавить();
        ДвТП.ВидДвижения     = "Расход";
        ДвТП.Номенклатура    = Строка.Номенклатура;
        ДвТП.Склад           = this.Склад;
        ДвТП.ЗаказПоставщику = this.ЗаказПоставщику;
        ДвТП.Количество      = Строка.Количество;
        ДвТП.Сумма           = НеттоСтроки;
    КонецЦикла;
КонецЕсли;
```

**Доработка формы:** добавить поле ЗаказПоставщику

## Управляемые формы (новые документы)

### ЗаказПокупателя — 3 вкладки

1. **Основное:** Номер, Дата, Организация, Основание (ref:Счёт), итоги (3 суммы)
2. **Покупатель и склад:** Покупатель, Склад, ТипЦенПродажи, СпособУчетаНДС, Комментарий
3. **Товары:** ТЧ + кнопки Пересчитать/Очистить

### ЗаказПоставщику — 3 вкладки

1. **Основное:** Номер, Дата, Организация, итоги (3 суммы)
2. **Поставщик и склад:** Поставщик, Склад, СпособУчетаНДС, Комментарий
3. **Товары:** ТЧ + кнопки Пересчитать/Очистить

## Проверка

1. Создать ЗаказПокупателя на 10 табуретов → провести → проверить РезервыТоваров (10 шт зарезервировано)
2. Создать Реализацию на основании Заказа → 5 шт → провести → РезервыТоваров остаток = 5
3. Создать вторую Реализацию → ещё 5 шт → РезервыТоваров остаток = 0 (заказ закрыт)
4. Создать ЗаказПоставщику на 100 табуретов → проверить ТоварыВПути
5. Создать Поступление на основании Заказа → ТоварыВПути остаток = 0
6. Проверить ФИФО: реализация с заказом списывает обычные остатки + снимает резерв
7. Проверить управляемые формы всех 4 документов
