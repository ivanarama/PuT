# План: Возврат от покупателя + Возврат поставщику

## Контекст

В конфигурации ПУТ (Программа Управления Торговлей) документ «Возврат от покупателя»
существует частично — есть YAML-определение и обработчик заполнения, но отсутствуют
валидация при записи и проведение. Документ «Возврат поставщику» не существует вовсе.
Оба документа необходимы для полноценного учёта торговых операций.

**Ссылочные документы для аналогии:**
- `src/списаниетоваров.posting.os` — шаблон ФИФО-запроса
- `src/реализациятоваров.posting.os` — проведение продажи
- `src/поступлениетоваров.posting.os` — проведение поступления

## Шаг 3. Создать `src/возвратотпокупателя.posting.os`

**Регистры:** ОстаткиТоваров, ПартииТоваров, Взаиморасчеты, ВаловаяПрибыль

### Логика проведения (обратная продаже):

1. Собрать потребность по номенклатуре (сводная карта)
2. ФИФО-запрос к `ПартииТоваров.Остатки` (тот же шаблон, что в `списаниетоваров.posting.os`)
   — для определения себестоимости возвращаемых товаров
3. Проверка достаточности: если остатков нет — fallback на цену продажи нетто
4. На каждую строку ТЧ:
   - **ОстаткиТоваров.Приход** — количество + ФИФО-себестоимость
   - **ПартииТоваров.Приход** — новая партия (ДатаПоставки = this.Дата), себестоимость из ФИФО
   - **ВаловаяПрибыль.Расход** — Выручка = нетто-сумма строки, Себестоимость = ФИФО-стоимость
5. **Взаиморасчеты.Расход** — одной строкой: Контрагент = Покупатель,
   ДокументРеализации = this.Основание, Сумма = this.Сумма

**Fallback при отсутствии ФИФО-остатков:** себестоимость = нетто-сумма строки
(Сумма - СуммаНДС). Это упрощение, но оно гарантирует, что проведение не упадёт.

## Шаг 4. Создать `documents/возврат_поставщику.yaml`

Новый документ, зеркальный к `поступление_товаров.yaml`:

```yaml
name: ВозвратПоставщику
title: Возврат поставщику
titles:
  en: Supplier return
  de: Lieferantenrücksendung
  sr: Повраћај добављачу
posting: true
based_on:
  - ПоступлениеТоваров
numerator:
  prefix: "ВПС-"
  length: 5
  period: year
fields:  # те же что у поступления + Основание
  - Номер, Дата, Организация, Поставщик, Склад
  - Основание (reference:ПоступлениеТоваров)
  - СпособУчетаНДС (enum, label: НДС)
  - СуммаБезНДС, СуммаНДС, Сумма (label: Всего к возврату)
tableparts:
  - Товары: Номенклатура, Количество, Цена, СтавкаНДС, СуммаНДС, Сумма
```

## Шаг 5. Создать `src/возвратпоставщику.os`

Три процедуры по шаблону `поступлениетоваров.os`:

### `ОбработкаЗаполнения()` — заполняется из ПоступлениеТоваров:
- Копировать: Организация, Поставщик, Склад, СпособУчетаНДС, суммы
- Основание = ДанныеЗаполнения.Ссылка
- Копировать все строки ТЧ

### `ПриЗаписи()` — аналогично поступлению:
- Валидация: Поставщик, Склад, ТЧ не пустая
- Дефолт СпособУчетаНДС, расчёт сумм и НДС по строкам
- Итоги в шапку

### `ПриДобавленииСтрокиТовары()` — автозаполнение СтавкаНДС

## Шаг 6. Создать `src/возвратпоставщику.posting.os`

**Регистры:** ОстаткиТоваров, ПартииТоваров, Взаиморасчеты

### Логика проведения (обратная поступлению):

1. ДатаПоставки основания = `this.Основание.Дата` — идентифицирует конкретную партию
2. На каждую строку ТЧ:
   - Расчёт нетто-суммы (Сумма - СуммаНДС, или Сумма при Сверху)
   - Запрос остатков конкретной партии (фильтр по Номенклатура, Склад, Организация,
     ДатаПоставки = дата основания)
   - Валидация: `КоличествоОстаток >= Строка.Количество`
   - Себестоимость из партии: `СуммаОстаток / КоличествоОстаток * Количество`
   - **ПартииТоваров.Расход** — из конкретной партии (ДатаПоставки = дата основания)
   - **ОстаткиТоваров.Расход** — по себестоимости партии
3. **Взаиморасчеты.Приход** — Контрагент = Поставщик,
   ДокументПоступления = this.Основание, Сумма = this.Сумма
